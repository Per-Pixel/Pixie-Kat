Validation checklist: provider price mismatch refund

UNIT FACTS (verified against prod logs):
- createorder returns `price` in Smile Points (e.g. 39) — the merchant Smile
  Points balance drops by exactly that amount.
- productlist SKU `price`/`cost_price` is in BRL (e.g. 4.00) — the productlist
  has NO Smile Points field. BRL and Smile Points differ by ~9.5x.
- Therefore the ONLY valid expected price is metadata.expected_provider_price
  set in Smile Points. The productlist BRL price is never used as an expected
  value (doing so fired the false "expected 4, got 39" mismatch).

Server: main/server/index.js
[ ] POST /api/fulfill-order with product.metadata.expected_provider_price = 39
    (Smile Points) and a createorder response of price '15' (cheaper substituted SKU)
    → calls adjust_wallet_balance with a positive refund amount
    → stores provider_mismatch with refund_status 'completed'
[ ] POST /api/fulfill-order with NO expected_provider_price set
    → does NOT crash, does NOT flag a mismatch, does NOT create a
      provider_mismatch entry (silent skip, log-only)
    → order completes normally
[ ] POST /api/fulfill-order where createorder price equals metadata.expected_provider_price
    → no mismatch, order completes cleanly
[ ] POST /api/fulfill-order with price in data.price, product_price, amount, or total_amount
    → extracts the price correctly in each case
[ ] POST /api/fulfill-order with a string containing spaces/currency symbols
    → normalizes to a number before comparison (defensive)
